# 四份核心文件规范

每个项目都在正式出图前建立这四份文件。文件内容必须具体、可审阅、可执行。

## design.md

建议结构：

- 项目目标与目标平台
- 原画面视觉分析
- 人物与字幕安全区
- 风格 A：色板、字体、版式、卡片、字幕、动效、适用气质
- 风格 B：同上
- 风格 C：同上
- 三套方案共同禁止项
- 用户选择
- 最终视觉规范
- 状态：待选择、已选定、已锁定

一图三风格前为候选版本；用户选图后更新成唯一规范。后续任何视觉修改都同步写回。

## script.md

建议结构：

- 标题
- 版本和确认状态
- 完整口播定稿
- 片尾口播
- 屏幕固定文字
- 品牌名与英文大小写
- 用户确认记录

原文与建议改写分开呈现。未确认的建议不能写进定稿正文。

## storyboard.md

每个场景使用一致字段：

- 场景编号和标题
- 时间范围
- A Roll 或 B Roll
- 口播原文
- 核心记忆点
- 构图与人物位置
- 屏幕文字与关键词
- 包装元素
- 动效和转场
- 素材需求
- 人物安全区
- 风险与检查点

时间范围应连续覆盖完整视频，不能出现无解释的空段或重叠。

## transcript.json

建议数据形状：

    {
      "language": "zh-CN",
      "source": "video-or-audio-file",
      "timing_status": "verified",
      "duration": 12.34,
      "segments": [
        {
          "text": "示例口播",
          "start": 0.0,
          "end": 1.2,
          "words": [
            {"text": "示例", "start": 0.0, "end": 0.55, "confidence": 0.98},
            {"text": "口播", "start": 0.58, "end": 1.2, "confidence": 0.97}
          ]
        }
      ]
    }

没有音频时：

- source 使用 script-only。
- timing_status 使用 pending_audio。
- duration、start 和 end 使用 null。
- 保留文字与词序，不估算假时间。

收到音频或视频后重新转写并替换为真实逐词时间。时间必须单调递增，单词必须处于所属片段范围内，最后一个词不得超过媒体时长。
